Etapa 01

Converta etiquetas ZIP, ZPL, TXT, PRN ou PDF em um PDF único

Envie arquivos .zip, .zpl, .txt, .prn ou .pdf. Arquivos ZPL são renderizados e PDFs já existentes são importados página por página, preservando cada etiqueta e preparando o documento para pesquisa, impressão e conciliação.

2 · Formato da etiqueta

Renderizando etiquetas…
O PDF gerado ou importado passa por uma limpeza da camada textual: a aparência visual da etiqueta é preservada, mas textos/OCR antigos e incorretos são removidos do PDF final. Em seguida, o sistema grava uma nova camada pesquisável estruturada apenas com dados confiáveis (NF, chave, destinatário, endereço, CEP, pedido e códigos), reduzindo erros na conciliação. PDFs enviados são tratados página por página, sem precisar passar pela conversão ZPL. A renderização usa a API pública Labelary (conversão ZPL → PDF) diretamente no navegador — nenhum arquivo é enviado para servidores da SmartCon Logistics. Se sua rede corporativa bloquear chamadas externas, hospede este arquivo em um domínio com acesso liberado a api.labelary.com.
Etapa 02

Concilie etiquetas com notas fiscais e gere a etiqueta de conferência

Selecione a plataforma e envie as etiquetas já convertidas em PDF e os PDFs das notas fiscais (DANFE). A V3 aplica pesos, limiares e validações diferentes por marketplace antes de aceitar qualquer vínculo. Cada perfil usa sinais adequados ao layout selecionado: Shopee Xpress prioriza pedido/rastreio + destinatário; Shopee Direta prioriza NF/Camada Limpa + endereço; Amazon DBA prioriza ORDER ID, nome, CEP e rua; TikTok usa validação fiscal mais rígida. a chave da NF-e é usada somente quando realmente existir no documento (com comparação aproximada para nome/rua/cidade, já que "Rua X, 06" e "R X Nº06" são o mesmo endereço escrito de formas diferentes) para conciliar automaticamente. Todas as etiquetas conciliadas são padronizadas em 100 × 185 mm. Pedidos com um produto recebem EAN, produto e quantidade no rodapé. Pedidos com vários produtos recebem um aviso no rodapé e uma página separada de conferência completa logo depois da etiqueta de envio.

Lendo arquivos…
A conciliação funciona assim: 1) em TikTok/iMile, a chave de acesso completa é obrigatória e deve ser idêntica; 2) em etiquetas Amazon sem chave, o sistema compara CEP, nome, rua, número, bairro e cidade; 3) o código do produto é usado apenas como confirmação quando estiver presente nos dois documentos — cada campo tem um peso (CPF/CNPJ sozinho já é decisivo; os demais se somam) e nome/rua/cidade usam comparação aproximada (fuzzy), então "Rua Laudelina de Almeida, 06" e "R LAUDELINA DE ALMEIDA Nº06" contam como o mesmo endereço. Cada página da DANFE é tratada como uma nota independente. O número da NF é decisivo; quando ele não existir, CEP, nome, rua e número são combinados por pontuação. O produto é definido exclusivamente pelo sistema. O sistema reserva primeiro todos os vínculos exatos por chave e número da NF, depois executa o match global um-para-um pelas informações do destinatário. Não existe confirmação manual de produtos. Quando uma nota possui mais de um item, todos os produtos seguem automaticamente para a página de conferência logo após a etiqueta de envio.
